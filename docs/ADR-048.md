# ADR-048 — Contextual related creation is one atomic Record-and-Connection action

**Status:** Accepted
**Date:** 25 August 2026

## Context

Connections are useful structure, but requiring an owner to navigate to a
second Table, create a Record, then reconstruct the edge turns that structure
into graph-shaped labour.

## Decision

The Record panel and full Record surface may offer `Add <target singular
label>` on an editable Connection. The selected parent is retained as the
visible context. The nested surface uses the target Object's real Fields and
Connections, permits progressive values, and automatically binds the exact
Connection that launched it.

`create_contextual_graph_record` is one security-invoker PostgreSQL operation.
It verifies active same-Business parent, Relationship and optional targets,
creates one generic Record, inserts the initiating edge and any selected
additional edges in the same transaction. Existing graph triggers remain
authoritative for RLS-visible membership, object/field validity, active status
and relationship cardinality. A failed edge therefore rolls back the new
Record instead of leaving an unexplained orphan.

Nested creation stops at one creation surface: its other Connections can select
existing Records through the existing picker, but cannot open another create
surface. This solves natural in-context work without recursive modal chains.

## Consequences

- The mechanism works for Company → Person, Opportunity → Follow-up, Customer
  → Pet, Job → Task and future metadata-defined graphs without specialised
  services.
- The browser never creates or stores a client-only relationship. The target
  Table is revalidated and both source and target Tables refresh after success.
- Existing connection search, display, inverse direction and cardinality
  semantics remain one system.

## Exclusions

No CRM module, relationship-specific service, automatic inferred propagation,
recursive create flow, public nested creation or new graph primitive is added.
