# ADR-051 — Table Workbench v0 keeps bulk, search and related values bounded

**Status:** Accepted
**Date:** 1 September 2026

## Context

ADR-036 deliberately deferred spreadsheet-style bulk actions while the direct
Table facade established its configuration boundary. The generic Internal
Workspace Engine now needs an owner to find and update ordinary Records at a
useful scale without turning a Table into a free-form database client.

## Decision

The Table Workbench remains one generic Table runtime over existing Objects,
Fields, Relationships, Records and Views.

- Search is transient, server-owned and bounded to the current View. It reads
  visible scalar values, Connection labels and configured one-hop related
  values; it accepts no query language, expressions or client-supplied tenant
  scope.
- Paging returns at most 50 Records to the workbench at a time. The query RPC
  retains the existing 250-Record hard maximum for trusted callers.
- Bulk update operates only on up to 100 currently loaded Records, one
  non-primary direct Field and a typed set or clear value. The RPC locks every
  selected Record, validates each currentness marker before any write, and
  commits all selected rows or none. It creates no configuration Change or
  Version.
- A connected Property is a read-only, single-valued, one-hop projection of a
  target Record Field. It is neither a copied Field nor a formula, rollup,
  write-through path or multi-hop traversal. Its accompanying connection is
  available only to open the connected Record context.
- View candidates remain component-memory only. They can hold up to 20 typed
  filters (all/any), five ordered sorts, one group, mixed-column visibility,
  order and bounded widths. One Save or Save as new produces one ordinary
  configuration Change and immutable Version; primary Tables remain canonical
  and unfiltered.

## Consequences

Owners work in familiar language—find, properties, related record and selected
Records—rather than SQL, graphs or raw configuration. Owner/Admin-only
structural controls retain configuration currentness. Staff retain the
authorised operational Table surface. The browser never receives a service
credential or a tool for arbitrary data queries.

## Exclusions

This does not introduce a spreadsheet primitive, selection persistence,
delete/archive bulk actions, customer-specific tables, formulas, rollups,
automation, arbitrary query text, a grid replacement, AI changes, Pages or
public/marketing changes.


## Table completion — 7 September 2026

The completion pass uses the existing query group metadata in the production
editor and the installed React Data Grid tree renderer. Group headings report
loaded and complete-query counts; collapse is local. Mobile uses the same group
model. Rectangular paste stays in ungrouped views; grouped views support cell
editing and explicit loaded-record bulk updates.

View candidates remain in component memory when a popover closes. Save and
Discard resolve them explicitly. Candidate previews are read-only, including
Record properties, and use their own count rather than the saved query's count.

Record writes return authoritative data without resetting the route. Once writes
settle, the containing workbench reloads the current search and loaded range in
50-record pages. Embedded tables refresh their containing route. A request
superseded by another search, view or write cannot replace the newer result.
Grid cell writes are serialized in entry order; optimistic and failed values
survive unrelated responses, and each failed cell has its own retry/discard.

Owner/Admin single-record archive and restore use the existing graph service,
record status, membership and RLS. The server re-resolves the internal Table
and verifies record ownership against its Object. The archive is a bounded
50-record list. There is no hard deletion, bulk archive, new Record storage or
configuration Version for these operational actions.

Column drag resizing now persists through the existing `resize_column` intent
and currentness boundary after a short debounce. This supersedes the editor
README's previous local-only resizing rule; it adds no configuration operation
or storage model. Repeated drag events for a column coalesce to its final width.
The property-removal work archives the Field and removes dependent view/form
configuration while retaining stored values; the owner confirmation states
that this affects every view of the Table.
