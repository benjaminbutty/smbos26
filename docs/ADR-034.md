# ADR-034 — Generic Record-to-Location availability

Status: Phase 12C is implemented on the feature branch and remains draft,
disabled, unqualified and unmerged.

## Decision

Availability is an operational association between one existing generic
Record and one first-class Location. Product and Equipment are acceptance
fixtures only; both use the existing `record_location_links` table, its
tenant/uniqueness/trigger protections and the existing trusted create/remove
operations. No new primitive, concept-specific table, availability history,
generic action registry or operational undo is introduced.

The generated Record detail experience gives Owner/Admin users a deterministic
one-pair control. New links may target active same-Business Locations. Existing
links to inactive Locations remain visible and are removed only by an explicit
unlink action. The Builder path accepts exactly one active eligible Record,
one existing Location and one `link_record_to_location` operational step.
PostgreSQL resolves the exact selector and pair state; candidate Records,
Record rows, UUIDs and link rows are not sent to the model or shown as a
chooser. Active preorder Order and Order Item Objects are protected by
trusted capability mappings; Product and other eligible generic Objects remain
available to the same path.

The model receives the unchanged configuration-only context. The signed
15-minute confirmation contains only the action, server-selected
Object/Record/Location identity, expected pair state, safe destination and
timestamps. It does not sign a display name or link-row ID. Final confirmation
is deterministic and AI-free: it rechecks tenant/capability, active eligible
Record, same-Business Location, active Location when linking and pair
currentness, then derives the current link row for unlink, calls one existing
trusted pair operation and verifies the result with an authoritative Location
name reload. It creates no configuration Version, Change, history or
operational undo.

The Phase 12C migration adds bounded preparation, one shared eligibility
helper and the symmetric protected unlink boundary; it does not add a second
final-state RPC or a new persistence primitive. Builder preparation and the
UI expose one finite `record_location_unavailable` reason contract plus one
success state. The new intent task remains globally/default and private-Builder
disabled during this implementation pass. No live qualification, reliability
run, private enablement, merge or Milestone 13 work is claimed. Phase 12A and
Phase 12B remain unchanged.
