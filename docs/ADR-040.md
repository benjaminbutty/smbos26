# ADR-040 — Separate acquisition contract gates from product-quality evaluation

Status: Accepted for v0.1 acquisition closeout

## Context

The anonymous acquisition evaluator originally treated every scenario finding
as one binary qualification gate. Repeated live testing showed that this
combined deterministic platform/trust-boundary failures with probabilistic
business-design choices. For example, a model can produce a valid generic
Objects/Fields/Relationships configuration while choosing a less useful
recurring-order model. The existing deterministic fallback, configuration
compiler, graph runtime and Connection services remain safe and reusable.

## Decision

Acquisition evaluation has two explicit lanes:

- The hard acquisition contract gate is merge-blocking. It covers production
  interpretation/composition failures, unsafe or forbidden capabilities,
  unsupported-capability misrepresentation, invented currency, prohibited
  technical owner language and the required deterministic acquisition landing
  contract.
- The product-quality scorecard records representative business-model findings
  such as missing concepts, preferred Relationship direction/cardinality and
  line-item modelling. Quality findings remain visible and can block product
  readiness decisions, but do not masquerade as unsafe configuration or fail
  the hard technical gate.

The evaluator uses deterministic complete word/phrase-component matching for
quality Relationship expectations and checks all matching endpoint candidates.
One-to-many orientation remains strict; many-to-many endpoint order remains
symmetric. No fuzzy, embedding or AI-based evaluator is introduced.

The planner receives only the minimal generic convention that a one-to-many
Relationship has the one side in `source_table_reference` and the many side in
`target_table_reference`. No business-specific schema, linking-record
validator, primitive or vertical module is added.

## Consequences

- Hard qualification and reliability results remain a trustworthy merge gate
  for the acquisition contract.
- Product-quality evidence is preserved for roadmap and v0 readiness review
  without encoding probabilistic business judgement as production validation.
- Existing Objects, Fields, Relationships, deterministic fallback,
  configuration lifecycle, graph/runtime and PR #38 Connection labels remain
  unchanged.
- The rejected local Relationship and linking-record experiments remain
  historical evidence and are not merged or pushed as production history.
