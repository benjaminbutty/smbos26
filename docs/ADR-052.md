# ADR-052 — Internal Pages document workspace and bounded operational content

**Status:** Accepted for the Internal Pages redesign
**Date:** 7 September 2026

## Context

Internal Pages need to feel like a calm document workspace while retaining
SMBOS's canonical Page grammar, immutable configuration history and shared
Table runtime. The existing editor checkpoint supports a bounded Tiptap
adapter, but it saves after a short debounce, has no lifecycle recovery, and
cannot express private media, collapsible sections or checklist presentation.
ADR-046's explicit save decision therefore conflicts with the approved product
contract for quiet automatic saving.

## Decision

- Internal document editing uses one in-memory Tiptap candidate translated to
  the canonical Page grammar. The candidate is saved automatically after a
  1.5 second quiet period and at most every 10 seconds during continuous
  typing. Cmd/Ctrl+S and intentional internal navigation flush it.
- A serial save coordinator owns title/body/lifecycle writes. It suppresses
  no-op writes, tracks revision numbers, never lets an older acknowledgement
  clear newer edits, and pauses after a failed or conflicting write until the
  owner retries or chooses a recovery action.
- Configuration acknowledgements read the exact committed Version returned by
  the atomic action and derive its committed head revision from the returned
  change set. They do not reread a later concurrent head as if it were the
  caller's acknowledgement.
- Page grammar remains finite and additive. A managed private media reference
  is mutually exclusive with a historical external image URL. Collapsible
  sections contain one level of bounded authorable blocks. Table View blocks
  may opt into a checklist presentation using two existing boolean/text
  Fields. Contained blocks count toward the existing 100-block limit and are
  traversed by every dependency and public-safety check.
- Checklist items are ordinary Records in an existing generic Object. A
  narrow composite configuration action composes the Object, Fields, View and
  Page reference atomically. Item ticks use the operational Record boundary
  and never create Page Versions.
- Private media uses one tenant-owned `media_assets` registry and a private
  `page-assets` Storage bucket. Authenticated narrow upload and asset routes
  validate membership and Owner/Admin permission; no persisted signed URL or
  browser service credential is used.
- Page duplicate/archive/restore actions preserve immutable page identity and
  shared Table, Record and media references. Duplicate allocation only creates
  a new Page identity and fresh block IDs.

## Consequences

The richer document experience stays within the existing Page and generic
Table primitives. It adds one reusable media registry and a bounded composite
configuration boundary, while preserving historical layouts, public Site
behaviour and operational data. ADR-046 is superseded for internal save timing
and expanded grammar; its Tiptap adapter and canonical persistence boundary
remain in force.
