# ADR-039 — Internal Workspace Engine uses mixed Table Views and typed queries

**Status:** Accepted for v0.1

**Date:** 10 August 2026

## Decision

SMBOS adds a reusable Internal Workspace Engine over the existing generic
primitives. Table Views use canonical V2 mixed field/Connection columns with a
primary or saved role. Historical V1 Table configurations are read through a
deterministic normalizer because M5 snapshots are immutable. Saved filtering,
sorting and grouping use a bounded typed query object; runtime reads and
operational Connection writes use narrow server-side RPCs.

Manual controls and future AI planning share the same allow-listed typed intent
boundary. The Builder and AI runtime surfaces remain unchanged.

## Consequences

- The platform supports connected Records without storing relationship IDs in
  Record JSON or creating custom tables per business concept.
- One active primary Table is used for navigation; saved Views are reusable
  entries in that Table's current-View selector and exact-key Page embeds.
- Query and Connection validation is duplicated at the application schema,
  configuration candidate and database runtime boundaries so clients cannot
  smuggle arbitrary SQL or predicates through the browser.
- Connection updates are operational data and do not create configuration
  history; structural changes remain M5 proposals and Versions.
- Formulas, workflow automation, collaboration, public editing and AI/Builder
  changes remain explicitly out of scope for this v0.1 boundary.
