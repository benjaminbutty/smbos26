# ADR-050 — Adaptive solution choice is deterministic and bounded

**Status:** Accepted
**Date:** 25 August 2026

## Context

An owner can describe a valid way of working while asking for a mechanism that
SMBOS must not execute literally. For example, combining two Tables can imply
a destructive Record migration, even when the real need is to work primarily
from one of them. Returning a generic unsupported result in that situation
was safe but unhelpful.

## Decision

Before Builder sends a request to the qualified planning task, a deterministic
resolver may recognise a bounded *one working surface* preference. It only
does so when the current Business configuration contains:

- a named active one-to-many Connection between the named Tables;
- a real internal Table for the preferred primary Table; and
- trusted configuration capabilities for each displayed consequence.

It emits a strict, owner-facing adaptive-choice result with no model-generated
options. The available consequences are fixed:

- **Use the current related workflow** — no configuration change, version or
  proposal; the server supplies a real primary-Table route.
- **Prepare a primary-centred adaptation** — re-enters the ordinary Builder
  planning and proposal lifecycle with an additive, non-migration constraint.

The signed, short-lived adaptive-choice continuation binds the original
request, presented choice, actor, Business and configuration currentness. A
selection may produce a normal clarification continuation; that continuation
retains the presented choice, selection and original request alongside its
answers, without asking the owner to reconstruct them.

## Consequences

- The owner receives an explanation of the present setup, the useful existing
  workflow, credible choices and the operational trade-off rather than a
  schema lecture.
- The literal merge is neither silently attempted nor dismissed as the only
  way to meet the owner’s goal.
- A configuration adaptation remains additive: it can add Properties and a
  focused View, but cannot merge, deactivate, archive, copy or rewrite
  operational Records or Connections.
- The established planner task, schema, policy and frozen planning subject
  are unchanged. Adaptive choice is deterministic pre-planning product logic,
  so it introduces no provider-backed task and does not supersede the existing
  planning qualification evidence.

## Exclusions

This is not a general help agent, persistent conversation, arbitrary
configuration execution, automatic Apply or a CRM-specific merge feature.
